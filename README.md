# Live Audio to Text: structure and automation setup

A web page records the microphone, shows a live waveform, and returns the spoken text.
Playwright tests it by feeding a prerecorded WAV file in place of a real microphone.

## Folder structure

```
automation/
  server.py                  Flask backend: serves the page, exposes POST /transcribe
  transcribe.py              Whisper speech-to-text (load_model, transcribe)
  templates/index.html       Frontend: record button, waveform canvas, transcript box
  requirements.txt           Python deps: flask, faster-whisper, av<17
  samples/test.wav           Test audio (4 short sentences, ~9.5 s, 16 kHz WAV)
  playwright.config.ts       Test setup: server, fake microphone, reporter
  tests/transcribe.spec.ts   The automated test
  package.json               Node deps: @playwright/test
  .venv/                     Python virtual environment (not for committing)
  node_modules/              Node packages (not for committing)
  playwright-report/         HTML report, generated by each test run
  test-results/              Traces and artifacts, generated by each test run
```

## How the app works

1. The browser opens `http://localhost:5000`. Flask returns `templates/index.html`.
2. "Start recording" asks for the microphone (`getUserMedia`). The audio feeds two things:
   - an `AnalyserNode`, which drives the waveform bars on the canvas, and
   - a `MediaRecorder`, which collects the audio.
3. "Stop recording" sends the audio to `POST /transcribe` as multipart form data.
4. `server.py` saves it to a temp file and calls `transcribe()` in `transcribe.py`.
5. faster-whisper (the `small` model, English, CPU, int8) returns the text as JSON.
6. The page shows the text in the transcript box.

The model is loaded when the server starts (`load_model()` in `server.py`), so the first
request is not slow. The first ever run downloads about 480 MB once.

Status hooks for tests: `#status[data-state]` goes `idle`, `recording`, `transcribing`,
then `done` or `error`. The transcript box has `data-testid="transcript"`.

## How the automation works

Playwright cannot speak into a microphone, so Chromium is told to fake one.

| Piece | Where | What it does |
|---|---|---|
| Fake device flags | `playwright.config.ts` `launchOptions.args` | `--use-fake-device-for-media-stream` replaces the mic. `--use-file-for-fake-audio-capture=samples/test.wav` makes the fake mic play that file. `--use-fake-ui-for-media-stream` skips the permission popup. |
| Permission | `permissions: ['microphone']` | Grants mic access to the page. |
| Server startup | `webServer` block | Playwright runs `.venv/bin/python server.py`, waits until port 5000 answers, and stops it afterwards. It reuses a running server if one exists. |
| Test steps | `tests/transcribe.spec.ts` | Open page, click Start, wait for the clip length, click Stop, wait for `data-state=done`, then check the text contains "transcription", "weather", "meeting", "thank you". |
| Reporter | `reporter: [['html'], ['list']]`, `trace: 'on'` | Writes `playwright-report/`, the pass/fail UI with traces. |

The fake mic only accepts WAV files, and it loops the file when it ends. The test therefore
waits the clip length plus 0.1 s before stopping (`CLIP_SECONDS` in the spec). If you change
`samples/test.wav`, update that number.

## Commands

```bash
# one time
uv venv --python 3.12 .venv && uv pip install -r requirements.txt --python .venv/bin/python
npm install && npx playwright install chromium

# run the app by hand
.venv/bin/python server.py            # then open http://localhost:5000

# run the automated test and open the report
npx playwright test
npx playwright show-report
```

## Decisions and fixes along the way

- Whisper backend instead of the Web Speech API: it works under Playwright, runs offline, and
  keeps audio local. The Web Speech API fails in Playwright's Chromium.
- `av<17` pinned: `av` 19 broke faster-whisper 1.2.1 (`metadata_errors` error).
- Language fixed to English (`WHISPER_LANGUAGE`, empty string means auto-detect): auto-detect
  returned Hindi for short English clips.
- Model loaded at startup: the first request used to hang while the model downloaded.
- Node test runner chosen for the report UI: the Python Playwright package has no built-in
  HTML report.
